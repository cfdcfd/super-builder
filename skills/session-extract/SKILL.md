# 会话信息提取

把一份已经发生过的对话，收成以后还能用的中文记录。输入是文件或目录，不读取 agentsview，也不依赖某一种产品的数据库。

脚本负责认格式、跳过噪音、按内容做增量。你负责判断什么值得留下，并且用简体中文写下来。

## 开始之前

- 需要 Python 3.11 或更高版本。只使用标准库。
- 状态放在当前目录的 `.session-extract/`。换地方用 `--state`，或设置 `SESSION_EXTRACT_HOME`。
- 日记写到 `memory/YYYY-MM-DD.md`，长期事项写到 `memory/事项.yaml`。用户指定了别的目录就照用户的来。
- 用户还没给出路径时，先问记录在哪。不要自己满盘去找。

能读这些形式：

- 带 `用户：` / `助手：`，或同样含义的 Markdown 标题。英文的 `User:` / `Assistant:` 也可以。
- 通用消息 JSON、JSONL：每条有角色和内容。
- Claude Code、Codex 这类编码代理写在磁盘上的 JSONL。
- ChatGPT 导出的 `conversations.json`。
- 用户明确指出的一个纯文本文件。整篇算作用户的一段话。

目录里没有说话人标记的说明文档、`package.json` 这类项目文件，不会当成会话。子代理目录（路径里有 `subagents`）默认不进入待处理列表。

## 步骤

### 1. 读入

```powershell
python <skill_dir>/scripts/extract_sessions.py ingest <记录路径>
```

看输出里的「摘要」。`新写入` 为 0 且进程退出码不是 0 时，告诉用户这份记录没认出来，并把「跳过」里的原因转述清楚。跳过很多文件时，按原因归类，不要把路径逐条念完。

### 2. 看进度

```powershell
python <skill_dir>/scripts/extract_sessions.py status
```

`待处理` 是 0 就停。没有会话时，按「提示」告诉用户先指定记录。

### 3. 取出下一批

```powershell
python <skill_dir>/scripts/extract_sessions.py fetch --limit 20
```

一次处理输出里的这些会话。需要看工具做了什么时加 `--include-tools`。某一天用 `--since` 和 `--until`，格式是 `YYYY-MM-DD`。

发言默认每条最多 2000 字。不够就对那一个会话执行 `show <编号> --max-content 0`。

### 4. 写当天日记

对每个会话，在 `memory/YYYY-MM-DD.md` 里按日期并进去，不要整文件覆盖。记录里自带时间的，用那个日期；没有时间的，用文件在本机的修改日期。一个会话两三句就够：谁在办什么事、结果怎样、有没有改口。

`timeline` 可以当草稿，不要原样粘贴：

```powershell
python <skill_dir>/scripts/extract_sessions.py timeline --since 2026-11-01 --until 2026-11-12
```

### 5. 写长期事项

只把过了下面这道门的内容追加到 `memory/事项.yaml`。拿不准的，留在日记里。

一条事项长这样：

```yaml
- id: 2026-11-12-登录只用短信
  类别: 决策
  内容: 这个产品的登录验证只用短信验证码。
  理由: 用户明确说不要用邮件。
  来源: notes/登录.md
  状态: 有效
```

类别只用这七个：`决策`、`事实`、`纠正`、`教训`、`偏好`、`待办`、`做法`。

以后的对话推翻了旧事项时，不要删旧的。把旧事项的 `状态` 改成 `已被取代`，并加上 `取代: <新事项的 id>`。

### 6. 提交进度

日记和事项都落盘之后再提交。这样中断了也只会把同一批再给你一次。

```powershell
python <skill_dir>/scripts/extract_sessions.py commit
```

输出里如果有「内容已变」，先重新 `fetch` 再看那几条，不要把没看过的新内容标成已处理。然后回到第 3 步，直到 `status` 的待处理为 0。

## 什么值得留下来

一条内容要同时满足这些，才写进事项：

1. 以后做类似的事还会碰到。
2. 只看代码或常识，一下推不出来。
3. 再发现一次要花时间，或者用户已经纠正过。
4. 现在仍然成立，不是一时的报错或即将删掉的文件。
5. 事项文件里还没有同样的话。有，就改原来那条，不另起一条。

优先从这些话里找：用户的纠正、定下来的选择和理由、失败之后真正走通的办法、项目里的规矩、环境里的怪癖、还没做完的下一步。

这些不要写进事项，日记里也只要一句带过：一次任务的流水账、大段工具输出、堆栈、闲聊、仓库里已经写明的话。

一次长对话通常只有几条事项。超过十条，就是门没把严。

## 用中文写

- 日记和事项都用简体中文。一句一事，写清是谁的、在什么条件下成立。
- 命令、路径、库名、配置键、报错原文保持原样，不要翻译。
- 用户用英文纠正时，用中文记下意思，并把关键词用引号留住。例如：用户要求提交说明用「why」，不要只写做了什么。
- 不写「值得注意的是」「进行了处理」这类空话。
- 会话里出现密钥、token、cookie、私钥时，不要照抄。写成「会话里出现过密钥，已省略」。

## 做法要不要变成技能

`做法` 如果是一整套还会再做的步骤，先在回复里用简体中文写出步骤草稿，问用户要不要存成技能。用户点头再写文件。不要趁这次提取直接改 `AGENTS.md` 或已有技能。

## 命令

| 命令 | 作用 |
| --- | --- |
| `ingest <路径>` | 读入文件或目录 |
| `status` | 会话数、已处理、待处理 |
| `fetch` | 给出下一批还没处理的会话 |
| `timeline` | 中文时间线，不看处理进度 |
| `show <编号>` | 看一个会话。编号里有空格时加上引号 |
| `commit` | 把最近一次 fetch 标成已处理 |
| `reset` | 清空进度，不删除已读入的原文 |

常用筛选：`--since`、`--until`、`--project`、`--source`、`--limit`、`--min-user-messages`、`--include-subagents`、`--include-tools`。`--source` 可以写 `markdown`，也可以写输出里看到的「Markdown 对话」。

编号、格式和发言角色都以命令输出为准。角色是「用户」「助手」「工具」。

## 例子

用户说：把 `D:\聊天记录` 里这段时间的对话记下来。

```powershell
python <skill_dir>/scripts/extract_sessions.py ingest D:\聊天记录
python <skill_dir>/scripts/extract_sessions.py fetch --limit 20
```

其中一段是：

```text
用户：登录不要用邮件。
助手：改成短信验证码。已改 src/auth.ts。
```

日记写：「登录验证从邮件改成了短信，动过 `src/auth.ts`。」

事项写一条类别为 `决策` 的记录：登录只用短信，不用邮件。来源写这条会话的编号。

然后 `commit`，再看下一批。
